# Development conventions

## Setup

```
python -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"     # Windows: .venv\Scripts\python.exe
```

## Before every commit

```
ruff check .
ruff format --check .
pytest -q
```

CI runs the same three commands on Python 3.11, and the JavaScript checks below on Node 24.

## Web version

```
node --test "tests/js/*.test.mjs"
python -m http.server 8790 --directory web
```

- Plain ES modules in `web/`: no framework, no bundler, no runtime dependencies ([ADR 0005](docs/adr/0005-web-version.md)).
- `web/engine.js` mirrors the Python engine; any change to the update rule must keep `tests/fixtures/patterns.json` passing in both languages.
- Interface text lives in `web/i18n.js` in English and Chinese; add every new string to both.
- Colours come from CSS variables in `web/style.css` (Okabe–Ito palette, safe for colour-blind viewers), with a dark-mode variant for each.

## Code

- Python 3.11, formatted with ruff (line length 100). `v1/` is kept as it was and is excluded from linting.
- States are boolean NumPy arrays; neighbour counts are integers. `step` never modifies its input.
- A new topology only needs a `neighbor_counts(state)` method. If it can represent a lattice, add a test that it agrees with `Lattice`.
- Engine cases that the web version should also pass go in `tests/fixtures/`.
- Key functions behind the experiments carry a structured docstring (in Chinese, with technical terms kept in English): what it does / how it is used in the experiments / why it matters / pitfalls / references.

## Documentation

- Each experiment gets `docs/experiments/0N-*.md`: question → prediction → method → results → discussion → limitations → open questions. The prediction is written before the experiment is run.
- Significant design decisions get an ADR in `docs/adr/`.
- Figures are generated by scripts or notebooks and saved to `docs/figures/`.

## Commits

- Small, focused commits with an imperative subject line.
- Tag `v2.0-alpha.N` after each experiment and `v2.0` at the end; update `CHANGELOG.md` with every tag.
